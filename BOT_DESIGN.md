# Telegram-бот «Напоминания об оплате» — структура и дизайн

## 1. Цель

Бот следит за датами платежей из `payments.csv` и шлёт напоминания в Telegram.
Напоминание повторяется **каждые 2 часа** в течение дня, пока получатель не
нажмёт кнопку **«✅ Выполнено»**. Если платёж не подтверждён до конца дня,
напоминания продолжаются на следующий день по тому же расписанию (платёж
считается просроченным, но не «протухает»).

## 2. Получатели и роли

| Роль | Кто | Что видит |
|---|---|---|
| **Owner** | Влад | Напоминания **по всем** платежам (и своим, и Игоря) |
| **User** | Игорь | Напоминания только по **своим** платежам (`source == "Игорь"`) |

Соответствие `source → chat_id` хранится в конфиге бота, т.к. в CSV его нет:

```yaml
# config.yaml (пример)
owner_chat_id: <chat_id Влада>
recipients:
  Влад: <chat_id Влада>
  Игорь: <chat_id Игоря>
```

Chat ID узнаётся через `/start` (бот сохраняет `update.effective_chat.id`
и просит владельца подтвердить, кто есть кто) — не нужно доставать его вручную
через сторонних ботов.

**Правило рассылки для платежа `P` с `source = S`:**
- всегда отправить владельцу (Владу);
- если `S != "Влад"` — дополнительно отправить получателю `recipients[S]`
  (чтобы Влад не получал напоминание дважды за один и тот же платёж).

## 3. Данные

### 3.1 Источник — `payments.csv` (read-only для бота, правит человек)

```
date,source,amount
2026-08-04,Влад,5600
2026-08-08,Влад,4600
2026-08-08,Игорь,4600
...
```

Рекомендация: добавить колонку `id` (стабильный идентификатор строки, число
или uuid), чтобы состояние в БД не «съезжало» при ручном редактировании CSV
(сортировка, вставка строк и т.п.):

```
id,date,source,amount
1,2026-08-04,Влад,5600
2,2026-08-08,Влад,4600
```

Если `id` не добавлять — ключом строки станет составной `(date, source, amount)`,
что работает, но ломается при полном совпадении двух платежей (дата+человек+сумма).

### 3.2 Состояние — `state.db` (SQLite)

Отдельная БД, куда при старте и по расписанию синхронизируется CSV.
CSV — источник истины по *данным платежа*, БД — источник истины по *статусу*.

```sql
CREATE TABLE payments (
    id          TEXT PRIMARY KEY,   -- из CSV, либо hash(date, source, amount)
    date        TEXT NOT NULL,      -- YYYY-MM-DD
    source      TEXT NOT NULL,
    amount      INTEGER NOT NULL,
    status      TEXT NOT NULL DEFAULT 'pending', -- pending | done
    done_by     TEXT,               -- кто нажал кнопку
    done_at     TEXT,               -- timestamp
    created_at  TEXT NOT NULL
);
```

**Синхронизация CSV → БД:** при старте бота и перед каждым тиком планировщика
бот перечитывает `payments.csv` (по mtime файла) и делает upsert новых строк
(`INSERT ... ON CONFLICT DO NOTHING`), не трогая уже существующие статусы.
Так можно дописывать новые платежи в CSV на лету, не боясь сбросить прогресс
по уже подтверждённым.

## 4. Расписание напоминаний

- Таймзона: `Europe/Moscow` (настраивается через env `TZ`).
- Тики: **09:00, 11:00, 13:00, 15:00, 17:00, 19:00, 21:00** — cron-триггер
  APScheduler (`CronTrigger(hour="9,11,13,15,17,19,21")`).
- На каждом тике:
  1. sync CSV → DB;
  2. выбрать из БД все `payments` где `date <= today AND status = 'pending'`;
  3. для каждого — отправить (новое) сообщение-напоминание нужным получателям
     (см. §2) с инлайн-кнопкой.

Планировщик — **один периодический job**, а не job-на-каждый-платёж: это
проще, переживает рестарт бота без персистентного jobstore и не требует
пересчёта расписания при правке CSV.

## 5. Telegram-интерфейс

### Сообщение-напоминание

```
💸 Напоминание об оплате
Дата: 08.08.2026 (просрочено на 2 дня)   ← если date < today
Кто платит: Игорь
Сумма: 4600

[ ✅ Выполнено ]
```

`callback_data = f"done:{payment_id}"`.

### Обработка нажатия кнопки

- `CallbackQueryHandler` ловит `done:<id>`;
- проверяет, что нажавший имеет право закрыть платёж (владелец — всегда,
  либо `source(payment) == текущий пользователь`);
- помечает `status='done', done_by=<user>, done_at=now()` в БД;
- редактирует нажатое сообщение → `✅ Оплачено 03.08.2026 в 14:32 (Игорь)`,
  убирает кнопку;
- если платёж закрыл не владелец — шлёт владельцу короткое уведомление
  «Игорь подтвердил оплату 4600 ₽ за 08.08.2026»;
- со следующего тика планировщика напоминания по этому `id` больше не шлются.

### Команды бота

| Команда | Действие |
|---|---|
| `/start` | Регистрация chat_id, приветствие |
| `/pending` | Список неподтверждённых платежей (свои, либо все — для владельца) |
| `/list` | Ближайшие платежи на N дней вперёд |
| `/help` | Справка |

## 6. Архитектура (модули)

```
reminder_bot/
├── config.yaml            # chat_id, таймзона, часы напоминаний
├── payments.csv            # исходные данные (правится вручную)
├── state.db                 # SQLite, создаётся автоматически
├── telegram.key              # токен бота (НЕ коммитить)
├── bot/
│   ├── __init__.py
│   ├── config.py           # загрузка config.yaml + telegram.key
│   ├── storage.py           # CSV-парсинг, sync CSV→DB, CRUD по state.db
│   ├── scheduler.py        # APScheduler, cron-тик, рассылка напоминаний
│   ├── handlers.py          # /start, /pending, /list, callback "done:*"
│   └── main.py              # точка входа: init bot, storage, scheduler, run
├── requirements.txt         # python-telegram-bot, APScheduler, PyYAML
└── reminder-bot.service     # systemd unit для AWS EC2
```

Стек: **Python 3.11+, python-telegram-bot (async, v20+), APScheduler, SQLite
(stdlib `sqlite3`), PyYAML**.

## 7. Развёртывание на AWS EC2

Уже готово:
- `ssh.command` — команда подключения (`ssh -i "osvc.pem" ubuntu@ec2-...`);
- `osvc.pem` — SSH-ключ (только для доступа с локальной машины, **на сервер
  не копируется**);
- `.venv` — локальное окружение (на сервере создаётся своё).

План деплоя:
1. `scp` каталог `reminder_bot/` (без `.venv`, без `osvc.pem`) на EC2 через
   `ssh.command`-хост;
2. на сервере: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`;
3. `telegram.key` кладётся на сервер отдельно (не через git), права `chmod 600`;
4. systemd unit `reminder-bot.service`:

```ini
[Unit]
Description=Payment reminder Telegram bot
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/reminder_bot
ExecStart=/home/ubuntu/reminder_bot/.venv/bin/python -m bot.main
Restart=on-failure
Environment=TZ=Europe/Moscow

[Install]
WantedBy=multi-user.target
```

5. `sudo systemctl enable --now reminder-bot`.

Обновление `payments.csv` в будущем: либо руками через `scp`/`vim` на сервере,
либо (расширение) через команду бота, доступную только владельцу.

## 8. Секреты и безопасность

- `telegram.key`, `osvc.pem` — в `.gitignore`, если каталог когда-либо станет
  git-репозиторием; сейчас репозитория нет, но правило соблюдаем на будущее.
- Права на ключевые файлы: `chmod 600 osvc.pem telegram.key`.
- Токен бота читается из `telegram.key` в рантайме, не хардкодится в коде и
  не логируется.
- Проверка прав в `done:<id>` handler'е обязательна — иначе Игорь сможет
  закрывать чужие (Владовы) платежи.

## 9. Открытые вопросы (нужно уточнить перед реализацией)

1. **chat_id** Влада и Игоря — получить через `/start` при первом запуске.
2. Нужно ли Игорю видеть *сумму и дату своих* платежей заранее (`/list`), или
   он должен узнавать только по напоминанию в день платежа?
3. Что считать «сегодня» для платежа в 00:00–09:00 — сразу слать в 09:00 того
   же дня (текущее решение) или ждать следующего тика?
4. Нужна ли предварительная напоминалка (например, за 1 день до даты) —
   в текущем дизайне нет, добавляется отдельным cron-тиком при необходимости.

## 10. Возможные расширения (не в MVP)

- Изменение/добавление платежей прямо из Telegram (только для владельца).
- Еженедельная сводка «сколько всего должно быть оплачено».
- Экспорт истории подтверждённых платежей обратно в CSV/Excel.
- Уведомление о новых просроченных платежах в отдельный «дайджест» раз в день,
  а не при каждом тике.
